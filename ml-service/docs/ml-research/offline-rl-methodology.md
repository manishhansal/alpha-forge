# Offline RL Methodology (Phase 3L)

How AlphaForge learns and evaluates execution policies from historical
trajectories without uncontrolled online exploration.

---

## 1. Why Offline

Online RL exploration against a market simulator risks learning to exploit
simulator artefacts and cannot be run against live capital in this phase.
AlphaForge therefore prefers OFFLINE RL: policies are learned from fixed
trajectories generated by deterministic behavior policies (spec §27).

## 2. Trajectory Dataset

Each trajectory is a sequence of `(observation, action, reward, next_observation,
done)` transitions, each tagged with `timestamp`, `instrument`, `policy_id`
(the behavior policy that produced the action), and `execution_version`
(spec §28, §29). Trajectories are stored in an IMMUTABLE registry with a content
hash; rewriting is rejected and integrity is verifiable (spec §72).

## 3. Behavior Policy

The behavior policy is always recorded (TWAP, VWAP proxy, fixed participation,
passive, aggressive, next-open). For OPE it is estimated empirically per binned
state and epsilon-smoothed so importance ratios are finite.

## 4. Out-of-Distribution Protection

An offline agent must not freely choose actions the data does not support
(spec §30). A `CoverageModel` tracks action frequency and state-action coverage
and computes an OOD score. If the greedy action is OOD for a state, the agent
ABSTAINS and falls back to a deterministic baseline rather than hallucinating
execution quality.

## 5. Behavior Cloning

A behavior-cloning baseline learns the existing execution behaviour (most
frequent action per binned state) and is compared against both the deterministic
policies and RL (spec §31). It grounds "does RL do anything different?".

## 6. Learning Algorithm

Deterministic Fitted-Q iteration (tabular or linear), a batch offline analogue of
DQN. It bootstraps targets from the current value estimate over the fixed
dataset — no online interaction, fully reproducible.

## 7. Evaluation

Never naive replay. Off-policy evaluation (IS/WIS/DR/FQE) with uncertainty
(ESS/coverage/weight concentration/CI). Unreliable estimates return
`OPE_INSUFFICIENT_EVIDENCE`.

## 8. Discipline

Walk-forward train/val/OOS with embargo; HPO/seed/reward-weight selection on
train/validation only; final holdout used at most once (else
`FINAL_HOLDOUT_CONTAMINATED`).

## 9. Current State

The offline pipeline is verified on synthetic trajectories. With a deterministic
greedy target far from the epsilon-smoothed behavior mix, OPE honestly returns
`OPE_INSUFFICIENT_EVIDENCE`, so no offline policy is credibly valued or promoted.
