# Meta-Labeling Methodology — AlphaForge Phase 3F

**Version:** Phase 3F
**Last updated:** 2026-09-06
**Scope:** Indian equity and F&O daily bars (NSE/BSE)

This document covers the economic reasoning, mathematical definitions, and design decisions for the Phase 3F meta-labeling and probability calibration system.

---

## 1. The Core Architecture

Phase 3F answers a different question than Phase 3E:

**Phase 3E (ranking):** Which securities are relatively attractive at t?

**Phase 3F (meta-labeling):** Given that the ranker has identified security i as attractive, should we act on it?

The two layers must remain separate:

```
Primary Ranker → alpha_score (relative attractiveness)
                           ↓
                 Candidate selection
                           ↓
              Meta Model → RawProbabilityScore
                           ↓
                Calibrator → CalibratedProbability
                           ↓
               EV Engine → ExpectedValue
                           ↓
            Decision Layer → TAKE / SKIP / ABSTAIN
```

The primary ranker is never asked to produce probabilities. The meta model is never asked to independently discover direction — it is conditional on the existence of a primary alpha candidate.

---

## 2. The Semantic Contract

The most critical improvement in Phase 3F is the explicit type system:

| Value | Meaning | Range | Never confuse with |
|-------|---------|-------|-------------------|
| `AlphaScore` | Relative attractiveness | unconstrained | Probability |
| `RawProbabilityScore` | Un-calibrated model output | varies | CalibratedProbability |
| `CalibratedProbability` | P(success \| information at t) | [0,1] | Raw score |
| `ExpectedReturn` | E[return \| signal] | % | Probability |
| `ExpectedValue` | E[payoff × P] - cost | % | Probability |
| `Decision` | TAKE/SKIP/ABSTAIN/... | categorical | Probability or score |

The key rule: `clip(raw_score, 0, 1) ≠ calibration`. The pre-Phase-3F code violated this rule by returning `clip(raw, 0, 1)` as a "calibrated probability" when the calibrator was unfitted. Phase 3F removes this fallback entirely.

## 3. Meta-Label Construction

### 3.1 The meta-label is conditional

The meta model predicts P(primary signal succeeds), NOT P(trade succeeds independently). It is conditioned on:

```
given that primary_alpha_score > threshold
AND primary_side = LONG (or SHORT)
AND eligible cross-section size >= min_cs_size
```

### 3.2 Three canonical policies

**Policy A — Positive net outcome:**
```
meta_label = 1  if  net_return > min_net_return
```

**Policy B — Triple-barrier success:**
```
meta_label = 1  if  first_touch == TAKE_PROFIT
```

**Policy C — Risk-adjusted success:**
```
meta_label = 1  if  net_return > min_required
             AND mae > max_mae  (drawdown within limit)
```

### 3.3 Stacking leakage prevention

If the meta model is trained on predictions that were generated by a primary model which already saw the same training observations, the meta model will be overconfident — it will inherit the in-sample performance of the primary model.

The fix: collect OOS primary predictions fold-by-fold:

```
Fold 1: Train primary model on [T0..T1]
         → Generate predictions for [T1..T2]  ← OOS

Fold 2: Train primary model on [T0..T2]
         → Generate predictions for [T2..T3]  ← OOS

Collect all OOS predictions
→ Train meta model (these are now truly OOS from the primary model's perspective)
```

`build_meta_labels(require_oos=True)` enforces this at the code level by raising `RuntimeError` if any `MetaEvent.is_oos_primary_prediction=False`.

### 3.4 Outcome feature exclusion

The meta model must never receive current-event outcome fields as features:
- `gross_return`, `net_return`, `mfe`, `mae`, `first_touch`, `event_end_time`

These are the TARGET, not features. `validate_no_outcome_features()` raises `ValueError` if any outcome pattern is detected in the feature list.

## 4. Probability Calibration

### 4.1 What calibration means

A model output of 0.70 is calibrated if, historically, 70% of candidates scored 0.70 by the meta model actually succeeded. This is the reliability (calibration) curve.

Formally: for all p ∈ [0,1]:
```
P(Y=1 | score=p) ≈ p
```

### 4.2 Why clip(raw, 0, 1) is not calibration

Clipping a raw score to [0,1] only ensures the value is in range — it says nothing about whether the value actually corresponds to the observed success frequency. A model that outputs 0.9 for every candidate "passes" the range check but has ECE = |0.9 - 0.5| = 0.40 (terrible calibration).

### 4.3 Two calibration methods

**Platt scaling (logistic):**
```
P(Y=1 | score) = σ(a × score + b)
```
Fit a and b via maximum-likelihood logistic regression on OOS predictions. Works well when the score is monotonically related to P(success).

**Isotonic regression:**
```
P(Y=1 | score) = isotonic_regression(score, labels)
```
More flexible; preserves monotonicity. Requires ≥ 100 samples to avoid overfitting. Uses sklearn's `IsotonicRegression`.

### 4.4 CalibratorArtifact states

Every calibration attempt produces one of four explicit states:

1. **UNCALIBRATED** — calibrator not yet fitted (checked first)
2. **CALIBRATOR_MISMATCH** — model_id or model_version incompatible
3. **STALE** — calibrator older than `max_age_days`
4. **CALIBRATED** — valid calibrated probability produced

Transitions are deterministic and inspectable. `is_usable()` returns `True` only when status == CALIBRATED.

### 4.5 Walk-forward calibration

```
[T0..T_cal] → fit calibrator
[T_cal+1..T_eval] → evaluate calibration quality
```

The temporal invariant: `fit_end_time < eval_start_time` for every fold. This is asserted in code and verified by tests.

### 4.6 Calibration diagnostics

| Metric | Ideal | Interpretation |
|--------|-------|---------------|
| ECE | 0.0 | Expected calibration error (weighted avg gap) |
| MCE | 0.0 | Maximum calibration error (worst bin) |
| Brier | 0.0 | Mean squared error between P and Y |
| Log-loss | → −∞ | Negative log-likelihood |
| Slope | 1.0 | <1 = overconfident; >1 = underconfident |
| Intercept | 0.0 | Systematic bias |

## 5. Expected Value

### 5.1 Formula

```
EV = P(success) × E[win] + (1 − P(success)) × E[loss] − E[cost]
```

Key properties:
- **Asymmetric payoffs**: `E[win] ≠ |E[loss]|` by default
- **P must be calibrated**: PROBABILITY_UNCALIBRATED → no EV
- **Payoff must be historical**: fit_end_time < prediction_time (EV leakage protection)
- **Cost model**: explicitly `DATA_UNAVAILABLE` until broker data is loaded

### 5.2 EV leakage

If the payoff distribution (`E[win]`, `E[loss]`) is estimated including the current event's outcome, the EV calculation is circular — using future information to estimate the value of a current decision.

`PayoffDistribution.assert_no_future_leakage(prediction_time)` raises `RuntimeError` if `fit_end_time >= prediction_time`.

### 5.3 EV is a decision statistic, not a backtest

`EV > 0` is necessary but not sufficient for a tradable strategy. It does not account for:
- Portfolio constraints
- Execution uncertainty (slippage, partial fills)
- Turnover and capacity
- Model uncertainty
- Regime shifts

## 6. Abstention

### 6.1 Why abstain matters

The decision layer must be capable of saying "I do not know." Forced decisions under uncertainty are more dangerous than abstention.

ABSTAIN ≠ SKIP:
- **SKIP**: we have evidence the trade is not favorable
- **ABSTAIN**: we cannot make a confident determination (calibration absent, stale model, etc.)

### 6.2 Abstention reasons

See `DecisionReason` enum for all 11 abstention reasons. Every `ABSTAIN` decision carries explicit reasons in `decision_reasons[]`.

### 6.3 The abstention quality test

After implementation: compare the success rate and EV of:
1. All candidates (no abstention)
2. Non-abstained candidates only

If abstention improves quality → `ABSTENTION_VALIDATED`.
If abstention does not improve quality → `ABSTENTION_NOT_VALIDATED`.

Do not assume abstention helps — verify it.

## 7. Design Decisions

| Decision | Chosen | Rejected | Reason |
|----------|--------|----------|--------|
| Fallback for unknown model | 0.5 (neutral) | clip(raw_score) | clip treats raw score as probability domain |
| Calibration check order | UNCALIBRATED → MISMATCH → STALE | STALE → UNCALIBRATED | Unfitted artifact was returning STALE instead of UNCALIBRATED |
| Signal confidence in decomp | weighted_confidence | abs(weighted_score) | Score magnitude is not a probability |
| EV cost when unavailable | COST_DATA_UNAVAILABLE status | Set to 0 | 0 cost is a meaningful market state; absent ≠ zero |
| Stacking prevention | RuntimeError in build_meta_labels | Documentation-only warning | Programmatic enforcement is stronger than documentation |
| Outcome feature detection | ValueError in validate_no_outcome_features | Pattern-matching warning | Hard failure prevents subtle leakage |
| IVPrediction.confidence default | None (Optional[float]) | 0.7 (hardcoded) | 70% confidence is a specific market state; absent ≠ 70% |
| Meta-label is conditional | Yes — conditional on primary signal | No — discover direction independently | Otherwise meta model duplicates the ranker |
